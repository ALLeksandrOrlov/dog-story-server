## Исправленные ошибки

Первый прогон настоящего HTTP API дал 27 успешных проверок из 29. Обе ошибки
касались завершения сессии: если первый игрок двигался, а второй бездействовал,
удалялся первый и в рекорды попадало его имя. Ошибка воспроизведена на исходнике.
Теперь используются фактические индексы бездействующих игроков; удаление идёт
в обратном порядке. Новый тест перебирает все 16 сочетаний активности четырёх игроков.

Дополнительные регрессионные проверки выявили и закрепили исправления:

- Генератор предметов сохраняет накопленное время между тиками, период переводится
  из секунд в миллисекунды.
- Отрицательное время и переполнение счётчиков отклоняются до изменения состояния.
- Отрицательная пагинация возвращает 400 до обращения к PostgreSQL.
- Повреждённые percent-escape последовательности и нулевой байт в адресе дают 400.
- Символическая ссылка на индексный файл не позволяет выйти за каталог статики.
- Числовая конфигурация принимает целые JSON-числа; пустые дороги и некорректные
  параметры генерации отклоняются при загрузке.
- Дробная базовая скорость больше не обрезается при чтении из модели и сохранении.
- Произвольный суффикс пути рекордов не считается существующим endpoint.

## Сравнение поведения

`tests/support/contract_driver.cpp` прогоняет одинаковые запросы через исходный
и новый `RequestHandler`. Набор содержит 121 шаг: методы, карты, вход, токены,
разделение сессий, движение, время, завершение, рекорды, статические файлы
и восстановление снимков. Сравниваются статусы, заголовки и JSON-тела;
случайные токены нормализуются. База в этом сравнении заменена памятью.

Исторический эталон `tests/fixtures/api_contract.json` снят с отдельной сборки
исходного кода и оставлен неизменным. Он также содержит ошибочное удаление игрока.
В `tests/fixtures/api_contract_corrections.json` отдельно заданы точные исправленные
ответы для 9 затронутых шагов, включая токены, состояние и рекорды. Проверка не
пропускает эти шаги: сравнивает ответ целиком, проверяет контрольную сумму исходного
эталона и соответствие запросов каждой поправке.

```sh
python3 tools/check_contract.py build/build/Release/contract_driver
# Проверка отдельной исходной сборки по историческому эталону:
python3 tools/check_contract.py /path/to/original/contract_driver --baseline
```

Исходная сборка по-прежнему проходит 121 шаг без поправок. Для сборки исходника
с Boost 1.86 потребовалось только изменить инициализацию нулевого UUID
с `ZeroUUID{{0}}` на `ZeroUUID{}`. Его тесты не менялись. Обе реализации сравнивались
с одинаковыми версиями библиотек.

Параметр `--record` предназначен исключительно для записи эталона из проверенной
исходной сборки. Не используйте его для принятия несовпадений рефакторинга.

## Проверка с PostgreSQL

Нужны свободный порт 8080 и отдельная тестовая база. Сценарии создают таблицу через
сервер и добавляют записи; используйте временную базу, а не рабочие данные.

```sh
export GAME_TEST_DB_URL='postgresql://USER:PASSWORD@localhost:5432/TEST_DATABASE'
python3 tools/run_http_integration.py build/build/Release/game_server http_smoke.py
python3 tools/run_http_integration.py build/build/Release/game_server api_live_check.py
python3 tests/api_edge_check.py build/build/Release/game_server
python3 tests/runtime_failure_check.py build/build/Release/game_server
```

`http_smoke.py` проверяет периодическое сохранение, завершение процесса,
восстановление токена и позиции, завершение игрока и запись в PostgreSQL.

`api_live_check.py` проверяет карты, изоляцию сессий, авторизацию, JSON, движение,
границы дорог, сбор и доставку предметов, очки, автоматическое время и перезапуск.
Отчёт сохраняется в `.cache/api-check/report.json`. Для многократных прогонов
используйте новую тестовую базу, чтобы старые рекорды не вытесняли проверяемые записи.

`api_edge_check.py` проверяет ошибочные запросы, доступ к статике, 48 одновременных
подключений, 40 параллельных тиков и длину HTTP-ответа. При ошибке скрипты возвращают
ненулевой код и останавливают запущенный ими сервер.

## Восстановление исходного клиента

Изначально 30 файлов `static` и `data/config.json` возвращены из исходного снимка.
Последующее исправление загрузки меняет только URL jQuery в HTML
на локальный файл той же версии, добавляет саму библиотеку и две исходные модели.
Проверка `original_client_unchanged` проверяет исходные контрольные суммы после
обратной нормализации этой единственной замены URL; все добавленные ресурсы
закреплены в `tests/client-runtime.sha256.json`. Изменений игровых маршрутов, методов и JSON ради интерфейса не требуется.

Два ранее добавленных HTTP-сценария проверяют литерал `Courtyard` в HTML. Их код
оставлен нетронутым: `tools/run_http_integration.py` запускает точные копии скриптов
в отдельном временном каталоге с минимальной страницей из `tests/fixtures/http-static`.
Таким образом тест выдачи статического файла не зависит от оформления рабочего
клиента. Все проверки API, PostgreSQL и снимков в этих скриптах выполняются полностью.
Прямой запуск этих двух скриптов без обёртки проверял бы устаревшее название интерфейса.

Сам восстановленный клиент проверяет `tests/original_client_http.py`: сервер выдаёт
все 33 файла с проверенными контрольными суммами, API возвращает исходные описания
трёх карт, а вход, движение и получение состояния сохраняют ожидаемые поля.

```sh
python3 tools/verify_original_client.py
GAME_TEST_DB_URL='postgresql://USER:PASSWORD@localhost:5432/TEST_DATABASE' \
  python3 tests/original_client_http.py build/build/Release/game_server
```

Предыдущее заключение об отсутствии моделей в репозитории было неполным:
файлы `key.obj` и `wallet.obj` есть в соседнем исходном каталоге ресурсов.
Они восстановлены без изменений; изменять ссылки и подменять графику не требуется.

## Проверка загрузки карт и ресурсов

Исправлена выдача статики с query-параметрами (`/?`, `/index.html?v=1`, JavaScript
с параметрами кеширования). Query отделяется до декодирования URL, поэтому `%3F`
в имени файла не теряется. Маршрутизация query API сохранена.

`tests/client_resource_check.py` проверяет через HTTP страницы входа, игры и рекордов,
локальные JavaScript-зависимости, модели из каждого описания карты и контрольные
суммы всех 33 ресурсов. Он также проверяет равенство файлов с query и без query.
Запускается из интеграционного сценария исходного клиента и поэтому входит в CI.

Игровые unit-тесты, старые API-сценарии и исторический эталон не изменены.
Проверка ресурсов `original_client_http.py` обновлена только для нового списка
ресурсов и вызова дополнительных HTTP-проверок; ожидания игровых ответов сохранены.
Браузерный инструмент отклонил доступ к локальной вкладке политикой безопасности;
визуальная проверка и выполнение WebGL в этом прогоне не выполнены.

Результат после исправления загрузки: 30/30 CTest в Release и ASan/UBSan,
29/29 игровых HTTP-проверок, 37/37 граничных и параллельных сценариев,
63/63 HTTP-проверки клиентских ресурсов. Последние также прошли на сборке
с санитайзерами. Вход, движение и получение состояния выполнены для каждой
из трёх исходных карт. Существующие 16 защищённых файлов игровых тестов
побайтно совпадают с контрольными суммами.

## Проверка Docker-развёртывания

Основной запуск перенесён на Docker Compose: игровой сервер и PostgreSQL 16
работают в контейнерах. В Linux ARM64 / GCC 12 Docker-сборке прошли все 30 проверок
CTest. Исправлены отсутствие данных и статики в build-этапе и зависимость Dockerfile
от локального CMakeUserPresets.json; теперь используется явный Conan toolchain.

Профиль `test` выполнил внутри контейнера существующие HTTP-сценарии: 29/29 игровых
проверок, 37/37 граничных и параллельных, сохранение и восстановление, отказ фонового
сохранения, все исходные карты и 63 проверки клиентских ресурсов. Для него выделена
база `game_test`, отдельно от рабочей `game`.

На работающем Compose-стеке также прошла 21 проверка `tests/docker_smoke.py`,
включая два перезапуска сервера, авторизацию, движение, завершение игрока,
запись рекорда в PostgreSQL и восстановление снимка. Проверены все runtime-библиотеки
и запуск процесса с UID 10001. CI переключён на Docker build и этот профиль тестов.

Прежняя локальная запись рекорда и снимок перенесены; резервные копии оставлены
в `.cache/docker-migration`. Нативный сервер и временный PostgreSQL остановлены.
Инструкции запуска: [docker.md](docker.md).
